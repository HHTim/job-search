關於我

我是 Tim，在國泰世華銀行主導 AI 工具導入 SDLC，擔任跨 4 個部門的 AI Scrum Team 專案 Leader（兼 SA、PM）。 簡單說：我的工作就是讓 AI Agent 在真實的企業環境裡跑起來，而不是停在 demo 或 PoC 階段。

我的背景有點非典型——銘傳大學休閒管理系畢業，在長榮航空做了五年半地勤與貨運業務， 2023 年參加緯育 TibaMe Java 雲端養成班轉入軟體業。這段跨域歷練讓我在做 AI 導入時， 比純工程師更清楚業務端為什麼不想用、要怎麼讓工具真的被採用。

做過什麼

2026 年起在國泰世華銀行主導 AI 納入開發流程，定義「先定好邊界與驗收標準、AI 再產出」的開發模式，並在兩個真實專案實際落地。

  • 雲端以 Claude 為核心，基於行內 SDK 建構團隊專屬 Skill（Tool Use 的企業版實作），覆蓋需求轉規格、PR Review、自動測試等環節
  • 地端以 Gemma4 作為推理核心，將 OpenClaw 串接為團隊「第七人」，以 Agent 方式自動處理排程、會議紀錄、重複性工作流程；Skill 已交付維運並由其他團隊接手使用
  • 擔任 KPI 模組專案 Leader，自建規格產生 Skill：逐題追問需求直到待確認事項歸零，確保 AI 寫程式前有完整驗收標準，估算整體開發時間縮短 70～80%
  • 後端以 Java / Spring Boot 為主，熟悉 PostgreSQL、Oracle、Redis；Docker、GCP Cloud Run 有實際部署經驗；雲端持有 AWS AIF-C01 / CLF-C02 雙認證

Python 不是我的主力語言，但 Java 與 Python 同屬物件導向語言，核心思維相通； 搭配 Claude Code 的 AI 輔助開發，切換語言的摩擦成本極低。 RAG、MCP 是我接下來要系統深化的技術方向，目前已有企業資料整合與 Agent 工作流的實作基礎。

為什麼是光寶

AI Agent 在消費端已成熟，但在企業內部系統的落地仍然困難—— 資料散落各處、系統無 API、規範多。我在銀行做的事，本質上就是解這個問題： 把 Tool Use、Agent 工作流、企業資料整合的技術， 轉譯成業務端能接受、IT 能維護的可運作系統。

光寶 AI Agent 應用工程師的職責——串接雲端與地端模型、與 PO 合作交付可上線應用—— 和我目前做的事高度吻合，只是從銀行換到製造業的場景。 我想在更多元的產業情境裡繼續做這件事，把在金融業學到的落地方法帶進來， 同時在 RAG、MCP、Python 生態上繼續補深度。
